बाँस का कोंपल तब तक ऊपर नहीं बढ़ता जब तक उसकी जड़ें मज़बूत साबित न हो जाएँ। यही बात यहाँ भी
लागू होती है: जब तक टेस्ट सहमत न हों, आपका एजेंट "ठीक कर दिया" नहीं कह सकता।

> अंग्रेज़ी [README.md](../README.md) ही आधिकारिक स्रोत है। यह अनुवाद अंग्रेज़ी अपडेट से पीछे रह सकता है।

## समस्या

कोडिंग एजेंट ऐसी सफलता का दावा करते हैं जिसे उन्होंने जाँचा ही नहीं होता। वे टेस्ट चलाए बिना
कहते हैं "सभी टेस्ट पास हो गए", बग मौजूद रहते हुए उसे ठीक बता देते हैं, और बिल्ड टूटी रहने पर भी
अपनी बारी समाप्त कर देते हैं। आपको यह बाद में पता चलता है, और भरोसे का नुकसान बग से भी भारी पड़ता है।

Shoot इस चक्र को बंद करता है। जिस क्षण आपका एजेंट रुकने की कोशिश करता है, यह वहीं हस्तक्षेप करता है,
पूर्णता का दावा करने वाली भाषा पहचानता है, आपके प्रोजेक्ट के असली test/lint/typecheck/build कमांड
चलाता है, और यदि दावे टिकते नहीं हैं तो **रुकने से रोक देता है** — और एजेंट को असली एरर आउटपुट
थमा देता है ताकि वह काम जारी रखे।

## पहले / बाद में

Shoot के बिना, बारी बस समाप्त हो जाती है:

```
Claude: Fixed the bug — all tests pass now.
        [turn ends. the test still fails.]
```

Shoot के साथ, एजेंट रोका जाता है और उसे असली विफलता सौंपी जाती है:

```
🐼 Shoot: Not yet. You said "Fixed" — it isn't true yet. Here's what broke:

--- test: failed with exit code 1
--- command: npm test

✖ adds (1.87ms)
ℹ pass 0
ℹ fail 1

  AssertionError [ERR_ASSERTION]: 0 == 4
      at TestContext.<anonymous> (sum.test.js:6:10)
    actual: 0,
    expected: 4,

Fix the underlying problem and re-run the checks. Do not report success until they pass.
```

एजेंट इसे पढ़ता है, असली बग ठीक करता है, और फिर दोबारा कोशिश करता है। जब जाँचें वाकई पास हो जाती हैं:

```
🐼 Shoot: Nice work — test passed. Cleared to grow.
```

ऊपर दिए गए दोनों ब्लॉक Shoot का वास्तविक आउटपुट हैं, कोई नमूना नहीं।

## तुरंत शुरू करें

```bash
npx shoot-cc init
```

यह पूछता है कि कौन-से कमांड चलाने हैं (आपकी `package.json` से सुझाव देते हुए),
`.shoot.config.json` लिखता है, और `.claude/settings.json` में हुक रजिस्टर करता है। बस इतना ही।

> **पैकेज का नाम:** npm पर **`shoot-cc`** के रूप में प्रकाशित — सादा `shoot` नाम एक असंबंधित
> पैकेज के पास है। आप जो कमांड चलाते हैं वह अब भी `shoot` ही है।

एजेंट का इंतज़ार किए बिना, अभी जाँच लें कि यह काम करता है:

```bash
shoot verify
```

## यह कैसे काम करता है

आपके एजेंट के हर स्टॉप (और सब-एजेंट-स्टॉप) इवेंट पर Shoot:

1. हुक पेलोड के `last_assistant_message` से एजेंट का अंतिम संदेश पढ़ता है।
   (ट्रांसक्रिप्ट फ़ाइल से नहीं — वह असिंक्रोनस रूप से लिखी जाती है और इवेंट से पीछे रह सकती है।)
2. उसे **claim detector** से गुज़ारता है — 30 फ़्रेज़ पैटर्न, साथ में नकार और अनिश्चितता की जाँच
   करने वाली विंडो, ताकि "tests don't pass yet" और "are tests passing?" दावे न गिने जाएँ।
3. **कोई दावा न मिले तो चुपचाप बाहर निकल जाता है।** काम के बीच की सामान्य बारियाँ न छुई जाती हैं,
   न धीमी होती हैं, और ट्रांसक्रिप्ट में कोई निशान नहीं छोड़तीं।
4. दावा मिलने पर आपके कॉन्फ़िगर किए कमांड वास्तव में चलाता है — इस क्रम में:
   `typecheck → lint → test → build`, एक-एक करके, हर एक का अपना टाइमआउट।
5. सब पास → रसीद के साथ रुकने की अनुमति। कुछ भी विफल → `block` निर्णय, जिसके कारण में
   असली विफल आउटपुट शामिल होता है।

चरण 2–4 प्लैटफ़ॉर्म-निरपेक्ष हैं। केवल चरण 1 का पढ़ना और चरण 5 का लिखना होस्ट-विशिष्ट है, और वे एक
पतले अडैप्टर में रहते हैं — इसीलिए नया प्लैटफ़ॉर्म जोड़ना छोटा काम है।

### वह अनंत लूप जो हमें मिला, और उसे कैसे रोका गया

इसे साफ़ शब्दों में कहना ज़रूरी है, क्योंकि यही इस टूल पर भरोसा करने की वजह है: Shoot को एक
वास्तविक Claude Code सेशन के विरुद्ध जाँचा गया — केवल गढ़े हुए पेलोड पर यूनिट टेस्ट तक सीमित
नहीं — और उस असली रन ने एक ऐसा बग पकड़ा जिसे यूनिट टेस्ट संरचनात्मक रूप से पकड़ ही नहीं सकते थे।

एक शुरुआती संस्करण अपनी पास-रसीद `hookSpecificOutput.additionalContext` के ज़रिए भेजता था।
`Stop`/`SubagentStop` पर यह फ़ील्ड बातचीत को समाप्त होने देने के बजाय **जारी रखता है**।
नतीजा: एक *सही* सुधार से भी — पास → रसीद → बातचीत जारी → Claude दोबारा "tests pass" कहता है →
डिटेक्टर फिर चलता है → रसीद → फिर जारी। यह **नौ बार** लूप हुआ, जब तक Claude Code की अपनी
आंतरिक सीमा ने बारी को ज़बरदस्ती समाप्त नहीं कर दिया।

दो सुधार, दोनों रिग्रेशन टेस्ट से ढके हुए:

- **`stop_hook_active` की जाँच सबसे पहले होती है।** जब Claude Code यह फ़्लैग सेट करता है,
  तो बारी पहले से ही ज़बरदस्ती जारी रखी जा रही है, इसलिए Shoot तुरंत चुपचाप बाहर निकल जाता है —
  न दावा पहचान, न जाँच, न कोई आउटपुट। वहाँ पूरी प्रक्रिया दोबारा चलाना ही लूप को बनाए रखता है।
- **किसी भी अनुमति-पथ पर `additionalContext` नहीं।** रसीदें `systemMessage` का उपयोग करती हैं,
  जो बारी को दोबारा खोले बिना आपके टर्मिनल तक पहुँचती है। `additionalContext` केवल असली `block`
  के साथ ही सही है, और `block` अपना `reason` स्वयं लेकर चलता है। जिस टाइप ने यह गलती संभव बनाई थी,
  उसे हटा दिया गया है, ताकि वह चुपके से वापस न आ सके।

एक बार चलने वाला अकेला हुक इनवोकेशन जारी-रखी-गई स्थिति को कभी दोहरा नहीं सकता। इसे केवल एक
वास्तविक सेशन ही उजागर कर सकता था।

### सर्किट ब्रेकर

वास्तव में टूटा हुआ टेस्ट सूट आपको कभी फँसाना नहीं चाहिए। Shoot प्रति सेशन एक ही विफलता के लिए
लगातार ब्लॉक गिनता है, और उसे `.shoot/sessions/` में सहेजता है (हर हुक इवेंट एक नई प्रोसेस होती है,
इसलिए मेमोरी में गिनती हर बार रीसेट होकर कभी ट्रिगर ही नहीं होती)। एक ही विफलता के लिए तीसरे ब्लॉक पर
यह स्पष्ट रूप से पीछे हट जाता है और बारी समाप्त होने देता है:

```
🐼 Shoot: I've paused this 3 times now for the same failure (test failed). Something's
genuinely stuck, so I'm letting this through — but the checks still do NOT pass, and a
human should look at it.
```

*अलग* विफलता काउंटर रीसेट कर देती है — वह असली प्रगति है, लूप नहीं। डिफ़ॉल्ट 3 Claude Code की
अपनी 8-ब्लॉक सेशन सीमा से काफ़ी नीचे है, और `maxBlocksPerSession` की अधिकतम सीमा 6 तय है ताकि
आप कॉन्फ़िगरेशन से उस सीमा के पार न जा सकें।

## शून्य निर्भरताएँ, जानबूझकर

```
$ npm ls --omit=dev --all
shoot-cc@0.1.0
`-- (empty)
```

केवल Node के बिल्ट-इन मॉड्यूल। **कोई postinstall या preinstall स्क्रिप्ट नहीं। कोई नेटवर्क कॉल कभी नहीं।**
छिपी इंस्टॉल स्क्रिप्ट वाले दुर्भावनापूर्ण Claude Code हुक पैकेजों के ज़रिए वास्तविक सप्लाई-चेन हमले
हो चुके हैं — इसलिए Shoot को इस तरह बनाया गया है कि इसे एक ही बैठक में पूरा पढ़ा जा सके।
यदि कभी कोई रनटाइम निर्भरता जोड़ी जाती है, तो CI बिल्ड को विफल कर देता है।

इसके अलावा, चूँकि Shoot आपकी अनुमतियों के साथ स्वतः चलता है:

- **कॉन्फ़िग बदलने पर फिर से अनुमोदन ज़रूरी है।** `.shoot.config.json` रिपॉज़िटरी में कमिट होती है
  और उसके कमांड बिना पूछे चलते हैं — इसलिए एक पंक्ति बदलने वाला पुल रिक्वेस्ट Shoot को हर समीक्षक की
  मशीन पर मनमाना कमांड चलाने वाले औज़ार में बदल सकता है, और diff कोड जैसा दिखता भी नहीं। Shoot
  अनुमोदित कमांड का हैश gitignore किए गए `.shoot/trust.json` में रखता है (इसलिए कोई PR उसे नहीं
  बदल सकता)। कमांड बदलने पर सत्यापन **छोड़ दिया जाता है और स्पष्ट चेतावनी दी जाती है**, जब तक आप
  `shoot trust` चलाकर अनुमोदन न दें।
- **कैप्चर किया गया आउटपुट डिस्क पर लिखे जाने या कहीं भेजे जाने से पहले संशोधित (redact) होता है।**
  टेस्ट आउटपुट एजेंट के संदर्भ, आपके टर्मिनल और डिस्क पर `.shoot/history.jsonl` तक जाता है।
  पहचानी जा सकने वाली गुप्त-कुंजी आकृतियाँ कैप्चर के समय ही `[REDACTED]` से बदल दी जाती हैं।
- **CI के Actions पूर्ण commit SHA पर पिन किए गए हैं**, न कि ऐसे फ़्लोटिंग टैग पर जिन्हें दोबारा
  किसी और कोड पर मोड़ा जा सके।
- **रिलीज़ npm Trusted Publishing (OIDC) से होती है** — चुराने योग्य कोई दीर्घकालिक
  `NPM_TOKEN` मौजूद नहीं है, और प्रकाशित पैकेज provenance प्रमाणन के साथ आते हैं।

पहली दो बातें रक्षा की अतिरिक्त परतें हैं, गारंटी नहीं। [SECURITY.md](../SECURITY.md) (अंग्रेज़ी में)
स्पष्ट बताता है कि वे क्या कवर करती हैं और क्या नहीं — इसमें redaction के सभी पैटर्न की पूरी सूची भी है।

## कॉन्फ़िगरेशन

`.shoot.config.json`, जिसे `shoot init` लिखता है:

```json
{
  "mode": "block",
  "checks": {
    "test": "npm test",
    "lint": "npm run lint",
    "typecheck": "npm run typecheck",
    "build": ""
  },
  "timeoutSeconds": 120,
  "maxBlocksPerSession": 3,
  "verifySubagents": true,
  "platform": "claude-code",
  "scopeDriftWarning": true,
  "scopeDriftFileThreshold": 12
}
```

| कुंजी | डिफ़ॉल्ट | यह क्या करती है |
| --- | --- | --- |
| `mode` | `"block"` | `"block"` विफलता पर एजेंट को रोकता है; `"warn"` केवल बताता है, कभी नहीं रोकता। |
| `checks.test` | `""` | टेस्ट कमांड। खाली = छोड़ दिया गया, विफल नहीं। |
| `checks.lint` | `""` | लिंट कमांड। खाली = छोड़ दिया गया। |
| `checks.typecheck` | `""` | टाइपचेक कमांड। खाली = छोड़ दिया गया। |
| `checks.build` | `""` | बिल्ड कमांड। खाली = छोड़ दिया गया। |
| `timeoutSeconds` | `120` | प्रति-जाँच टाइमआउट। टाइमआउट विफलता गिना जाता है, और "timed out" के रूप में बताया जाता है। |
| `maxBlocksPerSession` | `3` | पीछे हटने से पहले एक ही विफलता के लिए लगातार ब्लॉक की संख्या। अधिकतम 6। |
| `verifySubagents` | `true` | `SubagentStop` की भी जाँच करें। सब-एजेंट भी उतनी ही आसानी से पूर्णता का दावा करते हैं। |
| `platform` | `"claude-code"` | किस होस्ट के हुक बोलने हैं। `"claude-code"` या `"codex"`। |
| `scopeDriftWarning` | `true` | पास हुआ बदलाव असामान्य रूप से व्यापक लगे तो सलाह जोड़ता है। कभी ब्लॉक नहीं करता। |
| `scopeDriftFileThreshold` | `12` | इतनी बदली फ़ाइलों से ऊपर वह सलाह सक्रिय हो सकती है। |

कुंजियों के क्रम से स्वतंत्र, जाँचें सदैव `typecheck → lint → test → build` क्रम में चलती हैं,
ताकि सबसे सस्ता संकेत पहले मिले।

| `shoot init` | इंटरैक्टिव सेटअप: प्लैटफ़ॉर्म चुनता है, कॉन्फ़िग लिखता है, हुक इंस्टॉल और रजिस्टर करता है। |
| `shoot verify` | सभी कॉन्फ़िगर की गई जाँचें अभी एक बार चलाता है। कोई विफल हो तो नॉन-ज़ीरो कोड से बाहर निकलता है। |
| `shoot doctor` | सेटअप की समस्याएँ पकड़ता है: गलत Node, गायब स्क्रिप्ट, मृत हुक रजिस्ट्रेशन, अननुमोदित कॉन्फ़िग। |
| `shoot trust` | कमांड बदलने के बाद उनकी समीक्षा करके अनुमोदन देता है। |
| `shoot stats` | आपके स्थानीय सत्यापन इतिहास का सारांश देता है। |
| `shoot status` | कॉन्फ़िग दिखाता है, और यह भी कि हुक रजिस्टर है **और उसकी स्क्रिप्ट अब भी मौजूद है या नहीं**। |
| `shoot uninstall` | Shoot की अपनी हुक एंट्रियाँ, कॉन्फ़िग और स्टेट हटाता है। आपके अन्य हुक को नहीं छूता। |

### `shoot doctor`

यह उन सेटअप विफलताओं को पकड़ता है जो अन्यथा सफलता जैसी दिखती हैं — सबसे ज़रूरी: वह हुक जो
रजिस्टर है लेकिन जिसकी स्क्रिप्ट गायब है, जो इंस्टॉल दिखते हुए कुछ भी सत्यापित नहीं करता:

```
🐼 Shoot: Let's check your setup.

  ok    Node version         v22.14.0
  ok    Working directory    /path/to/project
  ok    Config file          .shoot.config.json
  ok    Platform             Claude Code
  ok    Checks configured    test, lint
  ok    test command         npm test → package.json scripts.test
  FAIL  lint command         npm run lint — no "lint" script in package.json
                             → Add a "lint" script, or change checks.lint in .shoot.config.json.
  FAIL  Hook registration    no Shoot hooks registered for Claude Code
                             → Run `shoot init` to register them.

🐼 Shoot: 2 problems will stop verification from working. The → lines above say how to fix each one.
```

जब कुछ वाकई टूटा हो तो नॉन-ज़ीरो कोड से बाहर निकलता है, इसलिए यह pre-commit हुक या CI में काम करता है।

### `shoot stats`

हर सत्यापन परिणाम `.shoot/history.jsonl` में जोड़ा जाता है — केवल स्थानीय, कहीं भी भेजा नहीं जाता।
`shoot stats` इसे पढ़कर दिखाता है:

```
🐼 Shoot: Your verification history

  verifications   3
  sessions        1
  first / last    2026-07-31 .. 2026-07-31

  passed          1
  blocked         2

  pass rate       33% of verified claims

🐼 Shoot: Caught 2 completion claims that weren't backed by passing checks.
```

पास दर केवल उन दावों पर गिनी जाती है जिनका वास्तव में सत्यापन हुआ — वे बारियाँ जिनमें जाँचने के लिए
कुछ कॉन्फ़िगर ही नहीं था, बाहर रखी जाती हैं, क्योंकि उन्हें किसी भी तरह गिनना इस संख्या को बिगाड़ देगा।

## समर्थित प्लैटफ़ॉर्म

| प्लैटफ़ॉर्म | स्थिति |
| --- | --- |
| **Claude Code** | पूर्ण समर्थन। एक वास्तविक सेशन के विरुद्ध सत्यापित। |
| **OpenAI Codex CLI** | समर्थित। दस्तावेज़ित कॉन्ट्रैक्ट के अनुसार बनाया गया; किसी वास्तविक Codex सेशन में अभी सत्यापित नहीं। |
| Cursor | अभी नहीं — `stop` हुक मौजूद है, पर यह CLI में चलता है या नहीं, अपुष्ट है। |
| Kiro | अभी नहीं — हुक मौजूद हैं, पर ब्लॉक करने योग्य completion इवेंट की पुष्टि नहीं हुई। |
| Antigravity | अभी नहीं — कोई तुलनीय हुक सिस्टम नहीं मिला। |

`shoot init` `.claude/` या `.codex/` देखकर पहचान लेता है कि आप कौन-सा प्लैटफ़ॉर्म उपयोग कर रहे हैं,
और तभी पूछता है जब पहचान न हो सके। पूरा विवरण — जिसमें हर असमर्थित प्लैटफ़ॉर्म के लिए ठीक-ठीक क्या
रुकावट है — [docs/PLATFORM_SUPPORT.md](./PLATFORM_SUPPORT.md) में है।

Codex के दो अंतर पहले से जान लेना उपयोगी है: वहाँ `decision: "block"` का अर्थ है *इस कारण के साथ
जारी रखो*, न कि *रुकने से रोको* (दोनों से Shoot को अभीष्ट परिणाम मिलता है); और Codex `Stop` पर
`systemMessage` समर्थित नहीं करता, इसलिए पास रसीद आपके टर्मिनल तक पहुँचती है, Codex UI तक नहीं।
`shoot init` आपको इस प्लैटफ़ॉर्म पर आगे बढ़ने से पहले यह बता देता है।

## स्कोप-ड्रिफ़्ट चेतावनी (केवल सलाह)

जब कोई दावा सत्यापन में पास हो जाता है, Shoot यह भी बता सकता है कि बदलाव असामान्य रूप से व्यापक
लगता है या नहीं — यह रसीद के साथ जोड़ा जाता है, कभी ब्लॉक नहीं करता:

```
🐼 Shoot: Nice work — test passed. Cleared to grow.
   Heads up (advisory, not a failure): 34 changed files across 6 areas — broader than a
   focused change usually is. Worth a glance if you expected something narrow.
```

**यह क्या है, यह साफ़ होना चाहिए:** फ़ाइल-गिनती पर आधारित एक अनुमान। यह git से पूछता है कि कितनी
फ़ाइलें बदलीं और वे कितनी बिखरी हुई हैं। यह कार्य-विवरण नहीं पढ़ता, बदलाव का उद्देश्य नहीं समझता,
और एक वैध व्यापक रीफ़ैक्टर तथा भटके हुए एजेंट में अंतर नहीं कर सकता। इसके लिए monorepo-व्यापी
रीनेम और असली ड्रिफ़्ट एक जैसे दिखते हैं।

इसीलिए यह किसी भी मोड में कभी ब्लॉक नहीं करता। इतने कमज़ोर संकेत पर ब्लॉक करना आपको Shoot की
अनदेखी करना सिखा देगा, और उसकी कीमत पकड़ी गई ड्रिफ़्ट से कहीं ज़्यादा होगी।
`"scopeDriftWarning": false` से बंद करें, या `scopeDriftFileThreshold` समायोजित करें।

## ज्ञात सीमाएँ

यह टूल क्या करता है और क्या नहीं, इस बारे में सीधी बात:

- **Shoot केवल वही कमांड चला सकता है जो आप उसे देते हैं।** यह ऐसे प्रोजेक्ट के लिए टेस्ट नहीं
  गढ़ सकता जिसमें टेस्ट ही नहीं हैं। बिना टेस्ट सूट वाले प्रोजेक्ट पर लगाने से इसके पास जाँचने को
  कुछ नहीं होता, और यह ढोंग करने के बजाय यह बात साफ़ कह देता है। सत्यापन बिलकुल उतना ही अच्छा है
  जितने अच्छे कॉन्फ़िगर किए गए कमांड हैं — सीधे `exit 0` करने वाला स्टब कुछ भी साबित नहीं करता,
  और Shoot यह अंतर नहीं बता सकता।
- **डिटेक्टर आलंकारिक प्रश्न-फिर-उत्तर रूप को नहीं पकड़ता।** `"Did I fix it? Yes."` नहीं पकड़ा जाता:
  प्रश्न-रूप मैच को दबा देता है, और उत्तर एक अलग उपवाक्य है जिसमें कोई दावा-फ़्रेज़ नहीं होता।
  इसे संभालने से असली प्रश्नों का दमन कमज़ोर पड़ेगा (`"Are the tests passing?"` को चुप रहना ही चाहिए),
  इसलिए यह जानबूझकर स्वीकारी गई कमी है, कोई छिपाई गई नहीं।
- **डिटेक्टर चुप रहने की ओर झुका है।** अनिश्चित दावे ("I think it's fixed", "almost done")
  गैर-दावे माने जाते हैं। अनिश्चित बात पर कड़ा ब्लॉक लगाना उचित नहीं, लेकिन इसका अर्थ यह भी है कि
  नरम दावे बिना जाँच के निकल जाते हैं।
- **दावा पहचान अनुमान-आधारित है, अर्थ-आधारित नहीं।** यह शब्द-रचना से मेल खाती है। नई तरह की
  शब्दावली बच निकलेगी — [claim-detection issue template][claims] इसी के लिए है।
- **स्कोप-ड्रिफ़्ट पहचान फ़ाइल-गिनती का अनुमान है, अर्थ-विश्लेषण नहीं।** ऊपर का खंड देखें — यह
  डिज़ाइन से ही केवल सलाह है और व्यापक रीफ़ैक्टर तथा असली ड्रिफ़्ट में अंतर नहीं कर सकता।
- **Codex अडैप्टर किसी वास्तविक Codex सेशन में सत्यापित नहीं हुआ है।** यह दस्तावेज़ित कॉन्ट्रैक्ट के
  अनुसार बना है और यूनिट-टेस्टेड है, पर वास्तविक एंड-टू-एंड उपयोग से Claude Code पथ ही गुज़रा है।
  Codex समर्थन को नया मानें।
- **Cursor का `stop` हुक CLI में नहीं चल सकता।** Cursor `stop` हुक दस्तावेज़ित करता है, पर उसके
  दस्तावेज़ यह नहीं बताते कि मानक एजेंट हुक `cursor-agent` के अंतर्गत चलते हैं या केवल डेस्कटॉप ऐप में।
  ऐसा अडैप्टर देने के बजाय जो CLI में चुपचाप कुछ न करे — ठीक वही विफलता जिसे Shoot रोकने के लिए है —
  पुष्टि होने तक Cursor असमर्थित है। यह प्लैटफ़ॉर्म की सीमा है, Shoot का बग नहीं।
- **झूठ बोलने वाला जाँच कमांड फिर भी झूठ बोलेगा।** Shoot एक्ज़िट कोड जाँचता है, टेस्ट की गुणवत्ता नहीं।

[claims]: .github/ISSUE_TEMPLATE/claim_detection.md

## अक्सर पूछे जाने वाले प्रश्न

**क्या इससे मेरा एजेंट धीमा होगा?**
सामान्य बारियों में लगभग नहीं। यदि अंतिम संदेश में पूर्णता का कोई दावा नहीं है, तो Shoot कुछ भी नहीं
चलाता और चुपचाप बाहर निकल जाता है — मापने पर लगभग **0.3 सेकंड**, जिसमें अनिवार्यतः सब Node प्रोसेस
स्टार्टअप है, और ट्रांसक्रिप्ट में कोई एंट्री भी नहीं छूटती। असली लागत (आपका टेस्ट सूट) आप तभी चुकाते हैं
जब एजेंट वाकई पूर्णता का दावा करता है — और वही क्षण है जब आप चाहते हैं कि जाँच चले।

**अगर मेरे पास टेस्ट नहीं हैं तो क्या?**
`checks.test` खाली छोड़ दें। कोई भी खाली कमांड छोड़ दिया जाता है, विफल नहीं गिना जाता — lint स्टेप न
होने पर प्रोजेक्ट को दंडित नहीं किया जाता। जो आपके पास है वही कॉन्फ़िगर करें; अकेला typecheck या build भी
असली संकेत है। कुछ भी कॉन्फ़िगर न हो, तो Shoot चुपचाप पास करने के बजाय आपको बता देता है।

**Claude से ही सत्यापन कराने में क्या दिक्कत है?**
क्योंकि इसमें एजेंट से यह अपेक्षा की जाती है कि वह काम भी करे और अपने काम का मूल्यांकन भी करे। जो एजेंट
टेस्ट चलाए बिना "tests pass" कह देता है, वह उतनी ही आसानी से यह भी कह देगा कि उसने सत्यापन कर लिया।
यह जाँच एजेंट के नियंत्रण से बाहर, हार्नेस में होनी चाहिए: Shoot स्वयं कमांड चलाता है, असली एक्ज़िट कोड
स्वयं पढ़ता है, और एजेंट इसे न छोड़ सकता है, न दोबारा व्याख्या कर सकता है, न विफल परिणाम को पास बता
सकता है। बात यह नहीं कि एजेंट अविश्वसनीय है — बात यह है कि स्वयं-घोषित सत्यापन सत्यापन ही नहीं होता।

**क्या यह Cursor या Windsurf के साथ काम करता है?**
अभी नहीं। आज Claude Code और OpenAI Codex CLI समर्थित हैं। Cursor `stop` हुक दस्तावेज़ित करता है
पर यह स्पष्ट नहीं कि वह CLI में चलता है, इसलिए आधे-अधूरे समर्थन के बजाय इसे जानबूझकर असमर्थित रखा
गया है — देखें [docs/PLATFORM_SUPPORT.md](./PLATFORM_SUPPORT.md)। सत्यापन इंजन हुक लेयर से
स्वतंत्र है, इसलिए नया प्लैटफ़ॉर्म जोड़ना एक छोटा अडैप्टर है, पूरा पुनर्लेखन नहीं।

**अगर जाँचें धीमी हों तो?**
वे केवल पूर्णता के दावों पर चलती हैं, एक-एक करके, और हर एक `timeoutSeconds` (डिफ़ॉल्ट 120 सेकंड) से
बंधी होती है। टाइमआउट को विफलता माना जाता है और टाइमआउट के रूप में ही बताया जाता है, इसलिए अटका हुआ
टेस्ट रनर आपका सेशन कभी लटका नहीं सकता।

**क्या यह हमेशा के लिए ब्लॉक करता रह सकता है?**
नहीं। सर्किट ब्रेकर एक ही विफलता के लिए `maxBlocksPerSession` लगातार ब्लॉक के बाद पीछे हट जाता है।
[सर्किट ब्रेकर](#सर्किट-ब्रेकर) देखें।

**क्या यह मेरे अन्य हुक छूता है?**
नहीं। `init` `.claude/settings.json` में मर्ज करता है और `uninstall` केवल Shoot की अपनी एंट्रियाँ
हटाता है — इसे एक राउंड-ट्रिप टेस्ट से जाँचा गया है जो यह सुनिश्चित करता है कि बाद में फ़ाइल बाइट-दर-बाइट
वही रहती है।

## रोडमैप

**आज जो मौजूद है:** दावा पहचान, टाइमआउट के साथ असली जाँच निष्पादन, block/warn मोड,
सर्किट ब्रेकर, स्टॉप और सब-एजेंट-स्टॉप इवेंट, Claude Code व Codex अडैप्टर, कॉन्फ़िग छेड़छाड़ पहचान,
गुप्त-कुंजी संशोधन, स्थानीय सत्यापन इतिहास, `doctor`, सलाहकारी स्कोप-ड्रिफ़्ट चेतावनी, सात CLI कमांड।

### विचार, वादे नहीं

नीचे सब कुछ **अनिर्धारित और आकांक्षात्मक** है। कोई तारीख नहीं, कोई वादा नहीं — ये केवल दिशा
दिखाने के लिए सूचीबद्ध हैं। इनमें से कई किसी और के दस्तावेज़ों पर रुके हैं, मेहनत पर नहीं।
पूरा विवरण [अंग्रेज़ी README](../README.md#roadmap) में है।

- **Cursor अडैप्टर** — Cursor `stop` हुक और `followup_message` फ़ील्ड दस्तावेज़ित करता है, जो
  Shoot की ज़रूरत के काफ़ी नज़दीक है। रुकावट यह है कि उसके दस्तावेज़ यह नहीं बताते कि एजेंट हुक
  `cursor-agent` (CLI) में चलते हैं या केवल डेस्कटॉप ऐप में। ऐसा अडैप्टर देना जो CLI में चुपचाप कुछ न
  करे, ठीक वही विफलता है जिसे यह टूल रोकने के लिए है — इसलिए पुष्टि की प्रतीक्षा है। देखें
  [docs/PLATFORM_SUPPORT.md](./PLATFORM_SUPPORT.md)।
- **Kiro अडैप्टर** — Kiro में हुक सिस्टम है, पर ब्लॉक करने योग्य completion इवेंट की पुष्टि नहीं हुई।
  केवल देखने वाले हुक झूठे दावे को दर्ज कर सकते हैं, रोक नहीं सकते। पहले AWS के वर्तमान दस्तावेज़ों
  से जाँच आवश्यक है।
- **Codex अडैप्टर का वास्तविक-सेशन सत्यापन** — दस्तावेज़ित कॉन्ट्रैक्ट के अनुसार बना और यूनिट-टेस्टेड,
  पर किसी वास्तविक Codex सेशन में कभी नहीं चला। Claude Code पथ चल चुका है; यह असमानता मिटनी चाहिए।
- **साझा करने योग्य आँकड़े** (`shoot stats --team` या समान) — उन टीमों के लिए जो अपनी
  झूठे-दावे पकड़ने की दर दिखाना चाहती हैं। असली डिज़ाइन समस्या यह है: दावा-पाठ और फ़ाइल पथ लीक किए
  बिना भी उपयोगी बना रहे।
- **गैर-अंग्रेज़ी दावा-पहचान शब्द-पैक** — डिटेक्टर आज केवल अंग्रेज़ी है। स्पेनिश, चीनी, हिंदी या किसी
  और भाषा में कहा गया पूर्णता का दावा पूरी तरह अनदेखा रह जाता है। पैटर्न तालिका पहले से डेटा है,
  तर्क नहीं — इसलिए यह मुख्यतः अनुवाद और परीक्षण का काम है, और अंग्रेज़ी-भाषी टीमों के बाहर सबसे
  ज़्यादा मायने रखने वाली कमी है।
- **वैकल्पिक GitHub Action रूप** — वही सत्यापन तर्क PR/CI समय पर चलाना, न कि केवल स्थानीय एजेंट
  हुक के ज़रिए। कोर पहले से प्लैटफ़ॉर्म-निरपेक्ष है, इसलिए पुनर्संरचना की ज़रूरत नहीं।
- **डॉगफ़ूडिंग डेमो वीडियो** — स्क्रिप्ट [DEMO.md](../DEMO.md) में तैयार है।

### जानबूझकर योजना में नहीं

- कोई डैशबोर्ड या होस्टेड सेवा। Shoot स्थानीय और ऑफ़लाइन ही रहेगा।
- अर्थ-आधारित स्कोप-ड्रिफ़्ट पहचान। आज की पहचान फ़ाइल-गिनती पर आधारित है और यह ईमानदारी से
  बताई गई है; उसे "समझदार" बनाने से वह आत्मविश्वास के साथ गलत होने लगेगी।
- प्रति-जाँच टाइमआउट, समानांतर जाँच निष्पादन, Git-सजग जाँचें। सभी उचित, कोई भी अत्यावश्यक नहीं।

## सुरक्षा

Shoot आपकी स्थानीय अनुमतियों के साथ स्वतः चलता है, इसलिए उसका थ्रेट मॉडल मान लेने के बजाय लिखा गया है:
**[SECURITY.md](../SECURITY.md)** (अंग्रेज़ी में)। इसमें बताया गया है कि ऊपर लिखी सुरक्षा-परतें वास्तव में
क्या करती हैं, स्पष्ट रूप से क्या नहीं करतीं, और भेद्यता की निजी रिपोर्ट कैसे दें (GitHub की निजी सुरक्षा
सलाह — कृपया सुरक्षा समस्या के लिए सार्वजनिक issue न बनाएँ)।

## योगदान

योगदान का स्वागत है — विशेष रूप से वे वास्तविक शब्द-रचनाएँ जो claim detector से छूट गईं। देखें
[CONTRIBUTING.md](../.github/CONTRIBUTING.md)। एक ही कड़ा नियम: **शून्य रनटाइम निर्भरताएँ**,
जिसे CI लागू करता है।

अनुवाद भी स्वागत योग्य हैं। अंग्रेज़ी README आधिकारिक स्रोत है; अनुवाद पीछे रह जाए तो PR भेजें।
